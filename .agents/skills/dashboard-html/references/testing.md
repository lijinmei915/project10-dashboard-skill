# Testing Guide

> 用途：给这个轻量 skill 提供最小人工验收方式，不引入自动化脚本。

## 建议测试方式

- 逐个使用 `references/test-cases.md` 里的输入触发 `$dashboard-html`。
- 检查输出是否明显沿用了 `assets/templates/starter.html` 的基础骨架，而不是每次重新发明一套布局。
- 每次输出后，先确认交付物是完整独立 HTML 页面，再按下面的验收清单检查页面结构、视觉一致性和多端适配。
- 若基础示例和至少 1 个复合 dashboard 示例都满足清单，可认为当前 skill 规则基本稳定。
- 每轮测试后可按 `references/test-log-template.md` 记录结果。

## 人工验收清单

### 1. HTML 交付

- 是否直接输出完整独立 HTML，而不是说明文字、伪代码或只给局部片段。
- HTML 是否至少包含完整页面骨架，如 `<!DOCTYPE html>`、`html`、`head`、`body`。

### 2. 页面骨架

- Report 是否由单一整页外壳统一承载；Dashboard 是否保持连续画布而不套报告式大容器。
- 是否有明确的 page header、section 或内容分组。
- 主内容是否保持统一宽度和左右留白。
- 是否可以看出与基础模板一致的页面壳层、卡片和栅格节奏。

### 2.1 页面类型

- 切换 Dashboard / Report 后，视觉预设名称和候选项是否随页面类型变化，同时保持当前主题、字号、间距、布局和单卡覆盖不变。
- 当前预设不属于目标页面类型的常规候选时，是否暂时保留为选中项；选择新的有效预设后是否再隐藏旧项。
- Dashboard 是否适合并列扫描和发现异常，Report 是否适合顺序阅读和理解结论。
- Dashboard 默认是否为全宽流式内容区，Report 默认是否保持阅读宽度。
- Dashboard 自动头部是否透明紧凑且与画布连续，Report 自动头部是否仍有独立 surface 承载。
- 头部对齐为 `auto` 时，Dashboard 是否居左、Report 是否居中；显式选择后是否保持用户设置。
- Report 是否保留包含头部和正文的整体圆角、细边界与轻阴影，Dashboard 是否明确移除这层外壳。
- Dashboard 省略分组标题时是否完全移除占位，并由卡片标题或 KPI 标签承担模块命名。
- Dashboard 省略分组标题后，设计模式悬停整组是否仍出现独立拖拽把手，并可交换整组位置。
- KPI 是否可全局或单卡切换上下/左右排列；面型图标是否为实心 SVG 图形本身，而不是线型图标叠加实色底。
- 卡片阴影是否提供无/轻/中/重四档，深浅模式下层级是否清晰且不改变卡片尺寸和布局。
- 标题图标形态与配色是否可独立组合；中性色与主题色是否支持全局和单卡覆盖，无图标时是否隐藏配色项。
- 用户主题原色达到目标对比度时是否保持原值；不达标时是否只调整明度，并分别满足大字/图形 `3:1`、普通文字 `4.5:1`。
- mock 报告的“客户健康与风险”是否支持中英文、整组排序、组内卡片换位和宽度调整。
- 进入“拖动整组”把手时是否高亮整组边界并暂时弱化单卡选中框，离开后是否恢复单卡状态。
- 悬停卡片时“拖动整组 / 拖动卡片”是否在当前卡片左上方紧凑并排，且分别对应整组与单卡高亮范围。
- 悬停卡片时左右两侧是否都显示宽度把手，向外/向内拖动是否按档位增大/减小并保存结果。
- 是否根据主要阅读任务选择 `pageType`，而不是只根据是否出现 KPI 或图表判断。
- 切换 `pageType` 时，视觉主题、深浅模式、主题色、字号、圆角、阴影、间距和数据是否保持不变。
- 是否没有为 Dashboard 和 Report 复制两套完整 HTML。

### 3. 卡片一致性

- 卡片是否使用一致的背景、圆角和内边距。
- 卡片标题字号是否来自独立 token，修改后不影响页面标题、分组标题和正文。
- 普通卡片标题图标是否默认关闭；启用后是否匹配卡片语义，并与 KPI 图标独立。
- 分组结构线、摘要分隔线、非语义重点数字和图表主系列是否来自派生 accent token，而不是各自写死颜色。
- `accent-on-soft` 与浅底文字对比度是否至少 `4.5:1`，`accent-structure` 与所在 surface 是否至少 `3:1`，实色主题底是否自动选择可读黑/白文字。
- 黑色、灰色、极亮黄色等边界主题色在浅色和深色模式下是否仍可辨认，不出现“跟主题但看不见”。
- Report 的外部画布、整页背景和卡片是否呈现同色相的弱染色三层；Dashboard 是否只保留连续页面与卡片两层。
- 背景跟随主题时是否仍然克制，没有把大面积 surface 直接染成高饱和主题原色。
- 页面纹理是否只出现在外部画布和页面底色，卡片内部保持纯色；导出的离线 HTML 是否仍能显示纹理。
- 自定义页面底色下，透明头部和分组标题文字是否对最终底色达到至少 `4.5:1`；卡片文字是否仍按卡片 surface 独立保持对比度。
- 图表配色是否提供单色、双色和彩色；单色和双色是否按色相距离从固定 AntV/G2 色板取最近一色或两色，且没有重算明度/饱和度；双色是否只用于真实的两组数据或二分类。
- 全局图表彩色时，单张图表覆盖为单色是否生效且不影响其他图表；恢复全局后是否删除覆盖属性。
- 单张 KPI 的图标样式与中性/主题配色是否只影响该卡；保存刷新和导出后是否保留，编辑选中框是否被移除。
- 单卡“标题图标”是否只在卡片内部标题真实可见时出现；Report 使用外部分组标题时，摘要卡不得显示无效的标题图标配置。
- 单系列柱状图是否避免无含义的奇偶深浅交替；分类色与卡片背景是否至少 `3:1`。
- 阴影和边框是否克制，不会一部分很重、一部分很轻。
- 页面底色与卡片底色相同时，是否至少保留极浅线框或阴影，卡片不能消失。
- 表格、列表、说明块是否各自位于独立卡片内。

### 4. 间距节奏

- section 与 section 之间是否有稳定纵向间距。
- 卡片之间的间距是否均匀。
- 卡片内部标题、正文、注释之间是否有清晰层次，而不是全部挤在一起。

### 5. 布局合理性

- KPI 区是否优先采用 2-4 列网格。
- 双栏区是否优先采用主内容在左、辅助区在右的轻量结构。
- 是否避免不必要的深层嵌套和过多装饰容器。
- 用户调整布局时，分组和卡片是否通过 DOM 顺序与 CSS Grid 重排，而不是绝对定位。
- 编辑模式下卡片是否可直接拖动，悬停尺寸把手是否不遮挡卡片标题和数据。
- 卡片跨度是否限制在预设档位，并在手机端自动恢复单列。
- 布局变化前后，数据、主题 token 和组件视觉是否保持一致。
- 手动保存配置后刷新是否恢复已保存快照；未保存修改刷新后是否丢弃；执行撤销时是否恢复上一版完整主题、布局和 Logo，而不是回到 HTML 初始默认。

### 6. 响应式

- 桌面端下信息是否有明确主次，不会被挤成窄列。
- 平板宽度下网格和双栏是否还能保持可读，而不是介于桌面和手机之间时失控。
- 窄屏下多列卡片是否会降为 2 列或 1 列。
- 双栏布局是否会堆叠成单栏。
- 关键信息在小屏上是否仍然容易扫描。
- 触控区域是否足够，不会出现按钮或交互项过小的问题。

## 常见不通过信号

- 输出不是完整 HTML 页面，而是建议列表或半成品片段。
- Report 的头部和正文散落在背景上，没有统一整页外壳。
- 卡片圆角、阴影、内边距前后不一致。
- section 间距忽大忽小。
- 为了“设计感”加入过重渐变、玻璃拟态、复杂动画或过多颜色。
- 只适配桌面端，手机端一收缩就出现拥挤、横向滚动或点击区域过小。
- 桌面端布局可以看，小屏一收缩就乱掉。
