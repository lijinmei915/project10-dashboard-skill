# Test Cases

> 用途：提供这套 `dashboard-html` skill 的手动测试用例，便于自测和记录问题。

## 使用方式

- 每次测试都直接触发 `$dashboard-html`。
- 先看是否输出完整独立 HTML，再看结构、样式和多端表现。
- 每个用例都记录“通过 / 不通过 / 备注”。

## Case 01: Basic Dashboard

### 输入

```txt
帮我做一个简洁的 dashboard 页面，重点统一卡片样式、区块留白和整体布局，同时适配桌面端和手机端，不要做得太重。
```

### 核验重点

- 是否输出完整 HTML 页面。
- 是否有统一外层容器和 section 分组。
- 是否沿用卡片式结构，而不是只给说明文字。
- 手机端下是否仍然能阅读。

## Case 02: KPI Overview

### 输入

```txt
帮我做一个销售概览 dashboard，首屏有 4 个 KPI 卡片，下面是趋势图和待跟进事项。页面保持简洁，重点统一卡片和留白，并适配手机端。
```

### 核验重点

- 是否有 2-4 列 KPI 卡片区。
- KPI 卡片是否统一为无边框、弱阴影、统一圆角和留白。
- 趋势图和待办是否分成独立卡片。
- 小屏下 KPI 是否会降列。

## Case 03: Status Page

### 输入

```txt
做一个简洁的系统状态页，包含页面标题、当前状态卡片、最近事件列表和说明备注，风格偏 dashboard，并适配手机端。
```

### 核验重点

- 是否保持轻量 dashboard 风格，而不是营销页风格。
- 状态、事件、备注是否分成独立卡片。
- 列表和说明层级是否清晰。
- 手机端下事件列表是否仍可扫描。

## Case 04: Table Panel

### 输入

```txt
帮我整理一个内部项目面板，上面放项目摘要卡片，下面放一个任务表格和右侧说明区，整体不要太花，并兼顾桌面和手机阅读。
```

### 核验重点

- 是否形成摘要区 + 表格区 + 说明区。
- 表格是否在独立卡片中。
- 桌面端是否形成主内容在左、辅助区在右的轻量双栏。
- 手机端下双栏是否堆叠成单栏。

## Case 05: Operations Dashboard

### 输入

```txt
帮我做一个运营 dashboard，顶部是 4 个 KPI 卡片，中间左侧放趋势图，右侧放异常提醒，底部放任务表格。要求输出完整独立 HTML，整体保持轻量，并适配桌面端、平板和手机端。
```

### 核验重点

- 是否输出完整 HTML 页面。
- 是否明显从 `assets/templates/starter.html` 的骨架演化而来。
- 是否形成 KPI 区、中部双栏、底部表格的稳定结构。
- 平板宽度下双栏是否仍可读。
- 手机端下 KPI 是否降列，双栏是否堆叠。

## 通用失败信号

- 输出不是完整 HTML 页面。
- 结构看起来像一次性拼接，没有统一外层容器。
- 卡片重新出现明显描边或偏重阴影。
- 复杂场景下又回到深层嵌套、花哨装饰或营销页视觉。
- 平板或手机端出现横向滚动、内容挤压、触控区域过小。
