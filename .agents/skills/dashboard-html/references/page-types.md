# Page Type Reference

> 用途：区分 Dashboard 与 Report 的选择条件和默认编排；不定义颜色、字体或具体业务模块。

## 配置

```txt
pageType -> dashboard | report
```

`pageType` 只控制信息密度、阅读顺序、头部编排、章节节奏和模块关系。视觉 token 由 `themes.md` 决定，内容和布局原语由用户需求与 `topic.md` 决定。

## 选择规则

| 用户意图 | `pageType` |
|---|---|
| 看板、监控、状态、概览、实时数据 | `dashboard` |
| 报告、分析、复盘、总结、周期经营 | `report` |
| 用户明确指定 | 使用用户指定值 |
| 无法判断 | `dashboard` |

同一句话同时包含两类意图时，以主要阅读任务判断：持续扫描和发现异常选 `dashboard`；顺序阅读和理解结论选 `report`。不要因为出现 KPI 或图表就自动判为 Dashboard。

## Dashboard

- 默认使用全宽流式内容区，只保留响应式页面边距，不设置全局最大内容宽度。
- 默认使用与页面画布连续的极简透明头部，不使用独立白色大容器、封面或外层大圆角。
- 页面标题和必要元信息保持紧凑；缺失内容直接隐藏，不自动加入操作按钮。
- 使用较高信息密度，模块可并列扫描。
- 同级内容优先 `grid`，有主辅关系时使用 `split`。
- KPI、图表、状态和明细都按请求生成，不作为必选模块。
- 当每张卡片已有明确标题时，默认省略分组标题且不保留空白；KPI 标签视为指标卡自身标题。
- 每个独立承载卡应有自身标题或明确标签；卡片边界用于区分模块。

## Report

- 默认整页报告外壳最大宽度为 `1000px`，窄屏自动占满可用区域；头部和正文在外壳内撑满可用宽度，不再叠加第二层内容宽度限制。
- 默认使用统一的整页外壳承载头部和正文，保留整体圆角、细边界与轻阴影；外壳内仍可维持 surface 头部与页面底色正文的层次。这层报告边界不跟随卡片线框开关消失。
- 自动头部使用独立 surface 承载，可按视觉主题改为浅色品牌底或主题色块。
- 自动头部默认居中；用户显式指定居左后不再覆盖。
- 使用标题、统计周期、创建人等必要元信息组成报告头部；缺失字段不补造。
- 内容优先按摘要、分析、明细、结论的阅读顺序组织，但只生成用户需要的章节。
- 图表可与解释文字组合，KPI 只在支撑结论时使用。
- 分组标题承担章节层级；连续叙事内容可以弱化卡片边界。

## 独立性

- 切换 `pageType` 不改变 `visualTheme`、`mode`、`accent`、字号、圆角、阴影和语义状态色。
- 切换视觉主题不改变 `pageType`、模块数量、内容顺序和布局结构。
- 不为两种页面类型维护两份完整 HTML；共用 starter token、布局原语和响应式基础。
- `pageType` 是默认编排策略，不是固定模板。用户明确指定结构时，以用户结构为准。
- 页面宽度和分组标题显隐采用 `auto` 时跟随 `pageType`；用户显式指定 `fluid/readable` 或 `visible/hidden` 后不再自动覆盖。
- 整页外壳由 `pageType` 决定：Report 保留，Dashboard 移除；切换卡片线框、圆角或阴影时不得顺带改变这条页面类型边界。
