# Color System

> 用途：定义 Dashboard Skill 的固定色板、颜色语义和组件取色规则。
> 什么时候更新：固定色值、颜色语义或跨组件取色规则变化时。
> 不要写什么：具体页面状态、视觉预设参数或组件布局。

## 数据源

固定色值以 `../assets/palette.v1.json` 为唯一数据源。Skill 只在需要生成颜色 token、图表、KPI 或分组标题时读取该文件；不得把完整图标库、图表库或额外色彩运行时打包进成品。

## 分类色

- 图表多色、KPI 多色和分组标题多色共用 `categorical`。
- `categorical` 固定包含 8 个基准色，按蓝、青、绿、黄绿、橙、红、洋红、紫的色相环顺序排列，并由紫回到蓝；各色应保持接近的感知饱和度和视觉强度，中性色不得混入分类色板。
- 按当前可见项目的顺序从索引 `0` 开始分配，隐藏项目不占色位；超过色板长度时循环。
- 多色使用 `categorical[i]`。
- 多色渐变使用 `categorical[i] -> categorical[(i + 1) % length]`，两端均为完整不透明色。
- 分类色不得跟随品牌色派生，不得调整色相、饱和度或明度。
- 颜色之外必须保留标签、图例、数值或形状区分，不得仅依赖颜色传达含义。

## 品牌色

- 品牌色由用户或企业主题提供，默认 `#ff8000`。
- 品牌色只驱动主题强调、单色图形及主题渐变，不改变固定分类色和状态色。
- 主题渐变可使用品牌主色与品牌相邻色；若企业主题提供 `brand.secondary`，优先使用明确的 secondary。
- KPI 等大面积主题单色浅底使用接近品牌色阶 `01` 的弱染色：浅色模式约 `4%` 种子色混入 surface，深色模式约 `10%`；不得从分类色板取代品牌色，也不得直接使用高饱和种子色铺底。
- 多色 KPI 浅底独立使用分类色弱染色，浅色模式约 `6%`、深色模式约 `12%`，不得与单色浅底共用同一个比例 token。

## 语义色与中性色

- 成功、提醒、危险、信息状态使用 `semantic.light` 或 `semantic.dark`，不按品牌色派生。
- 中性色用于页面、surface、文字、边框和禁用状态；组件只输出当前实际使用的 token。
- 普通文字目标对比度至少 `4.5:1`，大字和图形至少 `3:1`。必要的可读性适配只能影响承载面和前景选择，不得改写分类色身份。

## 企业覆盖

企业可覆盖 `brand`、整组 `categorical` 和 `semantic`，但必须保留字段名称、色板顺序和版本号。覆盖后的分类色仍使用相邻索引生成多色渐变。
