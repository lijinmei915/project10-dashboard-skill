# Output Rules

> 用途：存放这个轻量 skill 的 HTML 输出约束，避免把 `SKILL.md` 写得过满。

## 输出格式

- 输出必须是完整独立 HTML 页面，而不是说明文字、伪代码或局部片段。
- HTML 至少应包含 `<!DOCTYPE html>`、`html`、`head`、`body`。
- 默认从 `assets/templates/starter.html` 出发，再替换为真实内容。

## 页面目标

- 输出属于生成式 UI 场景下的各类 dashboard。
- 优先保证信息扫描效率、卡片分组和结构稳定性，而不是追求复杂装饰。
- 风格保持轻量，适合内部面板、状态页、概览页、简洁报告页。

## 不可丢失的基础骨架

即使用户要求“换一种布局”或“换成后台 dashboard 风格”，以下基础骨架仍应默认保留，除非用户明确要求推翻：

- 保留 page header，不要直接去掉页面标题区。
- page header 默认包含页面标题，以及一行辅助说明、状态信息或上下文信息。
- 主内容仍应保持单一居中容器，而不是散落为无边界的大画布。
- 大多数信息块仍应落在 card / surface 内，而不是直接裸露在页面背景上。

## 不可丢失的视觉基线

即使布局变化，以下视觉基线默认不应被替换掉：

- 卡片继续使用浅色 surface 背景。
- 卡片继续使用轻阴影，默认保持 `0 2px 10px rgba(15,23,42,0.04)` 这一量级。
- 不要因为布局变化而切换成明显更重的阴影、厚边框或悬浮感过强的卡片。
- 卡片圆角、内边距和 section 间距应保持前后一致，不要一部分很厚重、一部分很扁平。
- 若用户没有明确要求品牌化改造，不要自动引入强按钮风格、重色块头部或强视觉组件语言。

## 多端要求

- 不允许只优化桌面端。
- 页面必须兼顾桌面、平板、手机三个常见宽度。
- KPI 网格、多栏布局和辅助侧栏都需要在窄屏下自然收缩或堆叠。
- 触控场景下要保留足够点击空间，避免操作区域过密。

## 不建议输出

- 只给线框说明，不给完整 HTML。
- 只给桌面布局，不考虑手机端。
- 过重的视觉风格，如大面积玻璃拟态、复杂动画、强渐变堆叠。
- 脱离卡片式信息组织，导致 dashboard 不易扫描。
