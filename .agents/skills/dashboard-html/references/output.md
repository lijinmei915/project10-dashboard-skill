# Output Rules

> 用途：存放这个轻量 skill 的 HTML 输出约束，避免把 `SKILL.md` 写得过满。

## 输出格式

- 输出必须是完整独立 HTML 页面，而不是说明文字、伪代码或局部片段。
- HTML 至少应包含 `<!DOCTYPE html>`、`html`、`head`、`body`。
- 默认从 `assets/templates/starter.html` 出发，再替换为真实内容。

## 页面目标

- 输出属于生成式 UI 场景下的各类 dashboard。
- 优先保证信息扫描效率、卡片分组和结构稳定性，而不是追求复杂装饰。
- 风格保持轻量，适合内部面板、状态页、概览页、简洁报告页。

## 不可丢失的基础骨架

即使用户要求“换一种布局”或“换成后台 dashboard 风格”，以下基础骨架仍应默认保留，除非用户明确要求推翻：

- 保留 page header，不要直接去掉页面标题区。
- page header 默认承载页面标题，以及一行辅助说明、状态信息或上下文信息。
- 主内容继续保持单一居中容器，默认 `max-width: 1160px`；大多数信息块继续落在 card / surface 内，而不是散落为无边界的大画布。

## 不可丢失的视觉基线

即使布局变化，以下视觉基线默认不应被替换掉：

- 若用户没有明确要求重做视觉风格，默认不要重写 `assets/templates/starter.html` 里已有的样式基线。
- 若输出中继续使用阴影、圆角、间距等样式 token，默认直接复用 `starter.html` 中已有值，不要重新发明新的 shadow / radius / spacing token。
- 页面背景默认保持 `#f5f7fa`，卡片背景默认保持 `#ffffff`。
- 卡片继续使用弱阴影，默认保持 `0 2px 10px rgba(15,23,42,0.04)`。
- 卡片圆角默认保持 `14px`，卡片内边距默认保持 `20px`。
- `starter.html` 中的 `.chart-shell`、`.mini-chart`、`.stack-block` 只是占位状态；生成真实内容时应替换或移除可见占位框。
- 不要因为布局变化而切换成明显更重的阴影、厚边框或悬浮感过强的卡片。
- 卡片圆角、内边距和 section 间距应保持前后一致；若用户没有明确要求品牌化改造，不要自动引入强按钮风格、重色块头部或另一套组件语言。
- 更常见的做法应是保留现有样式系统，只替换占位内容、占位区域和布局填充。

## 多端要求

- 不允许只优化桌面端。
- 页面必须兼顾桌面、平板、手机三个常见宽度。
- KPI 网格、多栏布局和辅助侧栏都需要在窄屏下自然收缩或堆叠。
- 触控场景下要保留足够点击空间，避免操作区域过密。

## 不建议输出

- 只给线框说明，不给完整 HTML。
- 只给桌面布局，不考虑手机端。
- 过重的视觉风格，如大面积玻璃拟态、复杂动画、强渐变堆叠。
- 脱离卡片式信息组织，导致 dashboard 不易扫描。

## Checklist Before Delivering

- [ ] 输出是完整独立 HTML 页面
- [ ] page header 仍然存在
- [ ] 默认样式基线仍与 `starter.html` 一致
- [ ] 卡片阴影仍保持 `0 2px 10px rgba(15,23,42,0.04)`
- [ ] 没有无必要地新建另一套 shadow / radius / spacing token
- [ ] 真实图表、列表或内容区没有残留 starter 占位框
- [ ] 布局可以变化，但页面骨架和卡片系统仍然一致
- [ ] 桌面端、平板和手机端都已考虑
- [ ] 多列区域在窄屏下能自然收缩或堆叠
